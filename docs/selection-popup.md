# 原生 Mac 与跨平台划词浮窗

本次本地构建基于 CopyTranslator 12.1.0。M 系列 Mac 使用 **ARM64**，Intel Mac 使用 **x64**；Windows 目前仍提供 **x64**，两个平台共用浮窗、翻译引擎与设置。

## 安装与开启

Mac 安装包位于 `dist_electron/copytranslator-12.1.0-mac-arm64.dmg`，要求 macOS 13 或更高。退出旧版 CopyTranslator，打开 DMG，把应用拖到“应用程序”。目录中此前生成的 `mac-x64.dmg` 是旧构建，不包含本次划词浮窗改造。

本地包对完整应用和原生取词组件使用 ad-hoc 签名，以便 macOS 正确识别组件所属应用；没有 Developer ID 签名或公证。如果 macOS 阻止打开，可在“系统设置 → 隐私与安全性”中允许这个本地构建。

点击主界面左上角菜单，左侧栏的“剪贴板”分组后有“全局划词浮窗”开关；“设置 → 开关”中，相同设置卡片位于“进阶”后。关闭时只显示总开关；开启后展开触发方式、当前快捷键，以及 Mac 权限状态。“检查权限”刷新状态，未授权时可点击“打开辅助功能”打开系统权限页。允许 CopyTranslator 后切回应用会自动刷新；系统仍未放行时退出并重新打开应用。应用不会替你授予系统权限。

默认使用**点击小按钮**模式：在其他应用中拖选文字或双击单词后，会出现 CopyTranslator 自己的图标；点击才发送翻译请求并展开结果。按钮不会抢走焦点，点击外部、按 Esc 或 8 秒未操作时隐藏。

还可选择“选中后直接翻译”或“仅按快捷键翻译”。默认快捷键为 Mac `⌘⇧X`、Windows `Ctrl+Shift+X`；快捷键在任何模式下都能翻译当前选区，主开关关闭时不生效。仅快捷键模式不会在每次划词时读取选区。左侧划词设置卡片将“快捷键”和当前按键放在同一行，点击按键即可录入新组合；“设置 → 开关”也有同一入口。默认值可在按键的悬停提示和编辑窗口查看，注册失败时仍在卡片给出提示。保存立即生效，无需重启；占用冲突或保存失败会提示并保留原快捷键，已有其他自定义快捷键也会保留。

浮窗支持切换引擎、展开原文、复制、固定、调整大小和拖动位置；引擎列表在浮窗内部展开，支持滚动、方向键选择与 Enter 确认，点击当前引擎不会重复请求翻译；点击外部或按 Esc 关闭。固定后点击外部会保留浮窗。在按钮模式下，新的被动选区不会覆盖固定译文；按快捷键可更新。直接翻译模式则保留随选区更新的行为。

Windows ZIP 位于 `dist_electron/copytranslator-12.1.0-win-x64.zip`，解压整个目录后运行 `copytranslator.exe`。同样在“设置 → 功能开关”开启浮窗。安装版可以在 Windows 上用下面的构建命令生成。

- 浮窗使用已有的源语言、目标语言、智能互译和翻译引擎配置，也支持已配置的自定义供应商。
- 浮窗独立于“监听剪贴板”和旧的“拖拽复制”开关。两种划词功能同时开启时优先使用浮窗，避免重复翻译。
- 应用范围沿用“设置 → 拖拽复制”中的全局、白名单或黑名单。无需同时开启旧的拖拽复制。
- 选中的内容会交给你选择的翻译服务；开启前可先配置引擎和应用范围。

## AI 翻译商

主界面右上角引擎菜单改为“图标 + 名称”，单独显示“AI 翻译模型”分组。主界面菜单与划词结果浮窗都有“配置 AI 翻译商”入口，会直接打开相应设置页。没有启用模型时会显示空状态说明。

1. 添加供应商，填写服务商提供的 API 基础地址与 API Key。当前支持 OpenAI 兼容的 Chat Completions 接口；基础地址通常类似 `https://api.example.com/v1`。密钥框支持 Mac `⌘V`、Windows `Ctrl+V`，也可点击框内的“粘贴”按钮。
2. 在添加窗口点击“获取模型列表”，应用向服务商的 `/models` 接口查询，再从下拉框中选择一个或多个支持文本对话的模型。不提供列表或列表中没有所需模型时，直接输入准确的模型 ID 并按回车；无需先保存供应商。
3. 点击“测试连接”，用选定模型发送一次简短的 `/chat/completions` 请求，成功时显示模型、耗时和返回文本，失败时提示密钥、权限、额度、接口或网络问题。多选模型时可指定本次测试的模型。测试可能消耗少量服务商额度，获取列表成功不等于所有列出的模型都能翻译。
4. 点击“保存并启用”。主界面和划词浮窗都会列出已启用的“供应商名 - 模型名”，选择后才使用对应模型。保存后仍可编辑供应商、获取列表及启停模型。

API Key 与额度由服务商提供。新添加时需至少选择一个模型；旧配置中未启用任何模型的供应商不会出现在翻译菜单。主窗口选择 AI 模型后会关闭智能词典模式，让单词和句子都使用 AI 翻译。智能词典当前显示单词时，选择其他翻译引擎也会切换到译文；可在设置中重新开启智能词典。

模型启停与供应商名称修改会同步到各窗口，无需重启。获取到的候选列表在选择模型后保留；停用或删除模型会清理缓存条目。

## 实现与范围

macOS 使用一个 Swift 辅助进程，通过系统辅助功能接口读取选中文字。应用未提供该接口时，会短暂模拟 Cmd+C，随后在剪贴板仍属于这次操作的情况下恢复原有格式。Finder 文件拖动和密码框不会触发复制兼容方式。

预期适用于 Chrome、Safari 等浏览器正文，以及 Codex、VS Code 等应用中允许选中并复制的文字。不是按应用名称硬编码适配；是否可取词取决于该控件是否提供辅助功能选区，或支持复制。选区需要实际选中文字并松开鼠标，不是鼠标悬停或仅移动指针。按钮模式需点击图标；快捷键模式在选中后按下快捷键。

如果系统权限页显示已允许，而应用设置页仍显示未授权，可能是升级后旧版本的授权记录没有匹配到新包。系统日志已确认：仅关闭再打开开关可能仍保留旧版本的签名要求。这时应移除旧条目，重新添加 `/Applications/copytranslator.app` 并允许，然后回到应用点击“检查权限”。本地 ad-hoc 构建更新后可能需要重新授权。早期本地 ARM64 包没有对整个应用封装签名，会导致辅助进程被 macOS 当成另一个未授权的程序；当前构建已修正并增加包签名校验。

Windows 使用 `uiohook-napi` 监听选词手势；按需启动的 Windows PowerShell 工作进程优先通过 UI Automation 取词，再尝试 Ctrl+C 与剪贴板恢复。它不在后台轮询活动窗口。系统策略禁用 PowerShell、管理员权限应用、远程桌面或部分自绘控件可能限制取词。

不能保证“任意软件”都允许获取选中文字：图片内的文字、受保护内容、部分 PDF 或画布仍需使用原有截图/OCR 功能。此功能不会自动对整屏做 OCR。Linux 保留 X11 选区读取，需要 `xprop`；本次未验证 Linux，Wayland 的全局读取限制仍然存在。

## 百度翻译与 Dock

旧 v11 发布包包含百度兼容接口，而本仓库原有 `@opentranslate/baidu` 依赖仅走需要密钥的官方 API。空配置因此报认证失败。本次新增百度兼容适配器：用户自己的 APP ID 和密钥优先；两项留空时使用构建提供的兼容配置。认证、额度、网络和空结果错误会给出明确提示。

本地安装包沿用这台机器旧发布包中的兼容配置；配置仅保存在被 Git 忽略的 `.env.local`，以 `VUE_APP_BAIDU_LEGACY_CLIENT_ID` 注入，不提交到源码。其他机器自行编译时需提供其获准使用的构建配置，或在应用中填写自己的百度 APP ID 和密钥。兼容接口的长期可用性由百度决定。

macOS 默认显示 Dock 图标。“隐藏任务栏”在 Mac 上控制 Dock、在 Windows 上控制任务栏；浮窗使用 macOS 非激活面板（Electron `type: panel`）加入全屏 Space，同时保留 Dock。此前在普通 NSWindow 上设置 `skipTransformProcessType: true` 会导致窗口无法显示在全屏 Chrome 上方；面板窗口解决这一类型限制，并避免小按钮因未获取焦点而立即关闭。点击 Dock 图标会显示主窗口，即使此时有划词浮窗。

## 功耗方面

- M 系列 Mac 的主程序与辅助组件均为 ARM64，可直接运行，无需 Rosetta。
- Mac 剪贴板检测只定时读取原生变化计数；内容没有变化时不会读取文字、解码或反复转换图片。关闭 OCR 后不读取图片。
- 选词监听由鼠标按下/松开事件触发，不使用持续的鼠标位置轮询。
- 没有启用划词或双复制翻译时，不安装全局输入监听；全部功能关闭时也不会新启动辅助进程。
- 浮窗关闭后会取消显示旧请求的结果，并在 30 秒后释放其渲染进程。

这些改动减少了可确认的后台工作量。尚未做相同机器、相同负载下的瓦数或续航对比，不能据此给出省电百分比。Windows 剪贴板监听保留 750 ms 检测，尚未做同等程度的原生计数优化。

## 构建与验证

使用 Node.js 22.12 或以上、Yarn 1。Mac 需要 Xcode Command Line Tools。项目的 Vue CLI/webpack 4 仍需要 OpenSSL 兼容选项，专用构建脚本已处理。

```sh
yarn install --frozen-lockfile
npm run build:mac -- arm64   # M 系列 Mac
npm run build:mac -- x64     # 在 Mac 上交叉构建 Intel 版本
npm run build:win            # Windows：x64 安装包和 ZIP；Mac：交叉打包 x64 ZIP
npm run typecheck
npm run test:selection
npm run test:ai
node scripts/test-native-mac.js
node scripts/test-native-mac.js build/native/arm64/selection-helper --fallback
node scripts/smoke-mac.js
node scripts/smoke-mac.js --global  # 在受控测试应用中验证拖选到浮窗的完整流程
```

`prepare-dependencies.js` 对旧截图依赖 `shortcut-capture` 的 Electron 接口做了版本可检查、可重复执行的兼容补丁，只在截图窗口启用旧 remote 支持；划词浮窗使用隔离且沙箱化的 preload。
